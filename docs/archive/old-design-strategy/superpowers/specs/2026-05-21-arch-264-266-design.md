# Design: ARCH-264 + ARCH-266 — Domain type extraction and cockpit decomposition

**Date:** 2026-05-21
**Issues:** ARCH-264 (ROADMAP-008), ARCH-266 (ROADMAP-010)
**Approach:** Clean cut — no re-export bridges

---

## Context

Two coupled refactors run in sequence in a single session:

1. **ARCH-264** — Extract domain types from `project-store.ts` into neutral type modules so server modules no longer import from the Zustand store.
2. **ARCH-266** — Decompose the 1739-line cockpit route into server functions, hooks and a component shell.

ARCH-264 lands first so cockpit hooks can import from the correct modules from day one.

---

## ARCH-264: Domain type extraction

### Goal

`project-store.ts` becomes Zustand-only (~250 lines). All shared domain and pipeline types live in neutral modules that server code can import without touching client state.

### New modules

#### `src/types/project-state.ts`

All domain and pipeline types migrated from `project-store.ts`:

```
Address
ProjectData
PhaseName, PhaseStatus
HusDna
Byggeoenske
GeoJsonPolygon (internal helper type)
DesignPlacement
ComplianceFlag
BoligoenskeValidering
DataSourceStatus
DataSourceKind
DATA_SOURCE_LABELS
PipelineServiceState
PIPELINE_SERVICE_STATE_LABELS
```

Type guards and helpers that travel with the types:

```
isHusDna(v: unknown): v is HusDna
parseComplianceData(v: unknown): ParsedComplianceData | null
deriveSourceStatus(kind, value, lastFetchedIso): DataSourceStatus
STALE_DAYS (internal constant used by deriveSourceStatus)
```

#### `src/lib/compliance-flags.ts`

Pure function, no Zustand dependency:

```
deriveComplianceFlags(bbr, ramme, naturbeskyttelse?, dkjord?, geusRisk?, ruleEngine?, fjernvarme?): ComplianceFlag[]
```

Moves here from `project-store.ts`. This is also the target module for ROADMAP-014 (`reactive-compliance.ts` already imports this function).

### What stays in `project-store.ts`

- `create<State>()` Zustand store
- Internal `State` type (not exported)
- `DEFAULT_DATA_STATUS`, `DEFAULT_PHASES` constants
- All setters (`setAddress`, `setBbrData`, etc.)
- Re-export of `useProject`

No `export type` for domain types. No domain functions.

### Consumer updates

~35 files updated. Pattern:

```ts
// Before
import type { Byggeoenske, ComplianceFlag } from "@/lib/project-store";

// After
import type { Byggeoenske, ComplianceFlag } from "@/types/project-state";
```

Server modules that must no longer import from project-store:

- `src/integrations/supabase/project-persistence.ts`
- `src/lib/pre-check-adresse.ts`
- `src/lib/project-sync.ts`
- `src/lib/analysis-orchestrator.ts` (dynamic imports)
- `src/lib/rule-engine/input-assembler.ts`
- `src/integrations/ai/byggeanalyse.ts`
- `src/integrations/ai/hus-dna-generator.ts`

### Verification

`bunx tsc --noEmit` — any missed import is a compile error.
`bun test` — no regressions.

## ARCH-266: Cockpit route decomposition

### Goal

`src/routes/projekt.$id.cockpit.tsx`: 1739 lines → under 400 lines.

Route file becomes: route definition + auth wrapper + `CockpitPage` shell that composes hooks and tab components.

### New modules

#### `src/lib/cockpit.functions.ts`

The two `createServerFn` definitions moved verbatim from the route file:

```ts
export const fetchCompliance = createServerFn({ method: "POST" })...
export const runByggeanalyse = createServerFn({ method: "POST" })...
```

Route imports them. No logic changes.

#### `src/hooks/useCockpitRestore.ts`

Encapsulates the restore decision `useEffect` (~180 lines, currently at line 527 of the route).

```ts
function useCockpitRestore(params: { adresseId: string; authChecked: boolean }): {
  restorePhase: "pending" | "checked";
};
```

Reads from `useProject()` internally. Calls `restoreProject()` when needed. Does not own any data — restore writes go directly to store via existing setters.

Tests:

- "returns `checked` immediately when project data already matches adresseId"
- "triggers restoreProject and waits for pending when store is empty"

#### `src/hooks/useCockpitAnalysis.ts`

Encapsulates the analysis trigger `useEffect` and in-flight state (~200 lines, currently at line 708).

```ts
function useCockpitAnalysis(params: { adresseId: string; restorePhase: "pending" | "checked" }): {
  status: Status;
  fetchError: string | null;
  analysisSnapshot: AnalysisSnapshot;
  triggerAnalysis: () => void;
};
```

`AnalysisSnapshot` replaces the current 10+ individual `*Local` state variables:

```ts
type AnalysisSnapshot = {
  lokalplaner: Lokalplan[];
  geusRisk: GeusRiskData | null;
  servitutter: TinglysningResult | null;
  terrain: TerrainData | null;
  fjernvarme: FjernvarmeResultat | null;
  naboer: NeighborBuildingData | null;
  fbbData: FbbResultat | null;
  naturbeskyttelse: NaturbeskyttelsesResultat | null;
  dkjord: DkJordResultat | null;
};
```

Restore-owned data (bbr, complianceFlags, address) is read from `useProject()` directly in the consuming components — not mirrored here.

#### `src/components/cockpit/FreeDesignCockpit.tsx`

Moves these three components from the route file verbatim:

```
FreeDesignCockpit
FreeByggeoenskeAccordion
FreeBudgetEstimat
```

No logic changes in this move.

#### `src/components/cockpit/AnalyseTab.tsx`

Moves `AnalyseTab` (~280 lines) and all its passive sub-components verbatim:

```
AnalyseTab
LoadingView, ProgressRow, ErrorView
FjernvarmeSektion, NaboerSektion, ByggeanalyseKort
TerrainSektion, ServitutterSektion, GeusRisikoSektion
MetricCard, genererVurdering
```

These are all stateless/presentational — no logic changes. Moving them is required to hit the 400-line target; further decomposition is ROADMAP-021's job.

### What stays in the route file

- Imports + route helpers (`routeMatchesAddress`, `objectField`)
- `createFileRoute` definition and `Route` export
- `HardStopBanner` (25 lines — stays inline)
- `CockpitPage` — auth check (`useSession`, `authChecked`, `needsLogin`) + router guard
- `CockpitContent` — composes `useCockpitRestore`, `useCockpitAnalysis`, `<AnalyseTab />`, `<HardStopBanner />`

Estimated line count after all extractions: ~275 lines (well under 400).

### Import correction

All new hooks and `cockpit.functions.ts` import domain types from `@/types/project-state` (not `@/lib/project-store`) — correct from day one because ARCH-264 lands first.
