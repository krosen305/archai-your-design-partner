# Documentation Maintenance

Status: current documentation policy as of 2026-06-12.

ArchAI documentation has one rule: current product and architecture direction
must be easy to find, and historical implementation plans must not look like
active instructions.

## Product Direction

Current strategy:

> Address in -> documented preliminary building screening report out.

ArchAI is a B2B feasibility and due-diligence platform for professional users.
It is not currently optimizing for AI design, floor-plan generation, BIM,
one-click permit applications or tender workflows.

## Historical Documents

Historical implementation plans, generated specs and old product strategy docs
must live under `docs/archive/` or outside active documentation.

Archived documents are preserved for context only. They must not be used as
current implementation direction unless a new canonical document explicitly
revives that scope.

## What Does Not Belong In Active Docs

- Completed task plans and generated implementation specs.
- Prompt handoffs that mention old file shapes or old ARCH tickets.
- Old strategy docs centered on CAD, AI design, floor plans, BIM or permit
  automation.
- Migration notes that recommend temporary fallbacks after the fallback was
  removed.
- Verification summaries such as "tests passed" unless they are generated by CI.

Use Linear, PR descriptions, Git history and `docs/archive/` for task-state and
historical implementation context. Promote only durable product or architecture
decisions into the canonical documents above.

## Drift Checks

Before merging changes that touch integrations, persistence, routes, product
strategy or agent rules:

1. Search active `.md` files for `Dream to Draft`, `dream home`, `Hus-DNA`,
   `plantegning`, `BIM`, `myndighedspakke`, `udbud`, `one-click permit` and
   `Bureaucracy Killer`.
2. Any remaining mention must be explicitly marked as legacy, paused, archived
   or future-later scope.
3. Search active `.md` files for `projekter`, `DAWA REST`, `dawa.aws.dk`,
   `BBR Public`, `NaboService` and `api.dataforsyningen.dk`.
4. Confirm any `api.dataforsyningen.dk` mention is only GSearch autocomplete or
   map tiles, not compliance/register data.
5. Compare `docs/INTEGRATIONS.md` with `src/integrations/`.
6. Compare active Supabase tables with `supabase/migrations/`.
7. Update `AGENTS.md`/`CLAUDE.md` only when the rule itself changed and call out
   protected-file review.

## Strategy Lint

Run:

```bash
bun run strategy:lint
```

Alias:

```bash
bun run docs:lint
```

The lint checks active markdown guidance for old strategy terms. Mentions are
allowed only when the surrounding context clearly marks them as legacy, paused,
later, archived or not current scope.
